# Свежие вопросы и агент, который на них отвечает

Домашнее задание к семинару «ReAct-агент с нуля и цена верного ответа». Проверяем тезис курса
(«хороший агент на дешёвой модели обходится дешевле сильной модели в одиночку при том же
качестве») на вопросах о событиях, которых физически не могло быть в обучающих данных
Sonnet 4.6.

## Тема набора и откуда факты

Итоговый датасет `final_fresh.jsonl` — 148 вопросов о реальных событиях 2025–2026 годов с
коротким проверяемым ответом, ссылкой на источник и дословной цитатой, в которой этот ответ
содержится.

- **125 стартовых вопросов** (`source: "fresh"`) — из репозитория семинара, собраны скриптом
  `fetch_fresh.py` из более чем 60 обзорных статей Википедии про 2026 год (страны, наука,
  спорт). Из фактов с датами дешёвая модель сгенерировала вопросы, а оставлены только те, на
  которые Sonnet 4.6 без инструментов ответил неверно.
- **23 своих вопроса** (`source: "my"`) — добавлены отдельно, темы выбраны под свой профиль:
  релизы AI-моделей (Claude Opus 4.5, DeepSeek V4/V4.1-Flash, NVIDIA Rubin), инфраструктура
  (релизы и EOL Kubernetes 1.34), спорт (финал Лиги чемпионов УЕФА 2026), технологии и игры
  (Resident Evil Requiem, испытательные полёты Starship), а также два русскоязычных источника —
  приёмная кампания МФТИ 2026 и чайный аукцион Poly Auction Beijing. Источники — открытые:
  nobelprize.org, официальные пресс-релизы Anthropic/NVIDIA/DeepSeek/SpaceX, kubernetes.io,
  Wikipedia (en/ru), postupashkin.ru, tea.report.

## Как собирали

1. Для каждого факта нашли открытый источник и выписали дословную цитату, в которой ответ
   встречается буквально (проверяется автоматически: `normalize(answer) in normalize(evidence)`).
2. Сформулировали вопрос так, чтобы он был самодостаточен (понятен без чтения источника) и имел
   короткий однозначный ответ — имя, число, дата, название.
3. Прогнали `check_fresh.py` без ключа — проверка формата и дословности прошла без ошибок для
   всех 148 записей (уникальные `id`, обязательные поля на месте, длина ответа ≤80 символов).

## Что добавили к агенту из семинара

Базовый `ai_agent_01_documented.py` умел искать факты только по вступлению англоязычной
Википедии. Для датасета свежих вопросов (в том числе русскоязычных, с фактами вне Википедии)
этого не хватало, поэтому добавили новый набор инструментов и вспомогательных функций:

| Функция / инструмент | Что делает |
|---|---|
| `web_search(query)` | Инструмент агента. Поиск по всему открытому вебу через HTML-версию DuckDuckGo без API-ключа, работает на любом языке (в т.ч. русском); возвращает до 5 ссылок с заголовком, сниппетом и URL. Заменил исходный `web_search`, ограниченный англ. Википедией. |
| `read_page(url)` | Инструмент агента. Открывает конкретный URL и возвращает очищенный от HTML-разметки текст всей страницы (до 6000 символов), а не только вступление — именно это чаще всего давало недостающий прирост `agent_ok`, так как нужный факт обычно не в первом абзаце. |
| `final_answer(text)` | Достаёт финальный ответ агента по маркеру `FINAL:` из полного текста рассуждения. Сделана самодостаточной (не зависит от того, выполнялась ли ячейка Спринта 6 в ноутбуке), чтобы не ловить `NameError` при выборочном запуске ячеек. |
| `loose_match(gold, answer)` | Мягкая проверка совпадения ответа с эталоном по набору значимых токенов, а не по точному порядку слов и не по языку записи числа (приводит русские «трлн/млрд/млн» к T/B/M). Используется как запасной вариант в дополнение к строгой проверке подстрокой, чтобы не терять реально верные ответы из-за форматных расхождений вроде «March 15, 2026» vs «15 March». |
| `evaluate_fresh(path, model, tool_names, max_steps, traces_dir, verbose_every)` | Основной раннер: прогоняет агента по всему `.jsonl`-датасету, считает `agent_ok` (строгое ИЛИ мягкое совпадение), пишет трейс каждого вопроса на диск (`traces/fresh/<модель>/<id>.json`), печатает прогресс каждые `verbose_every` вопросов и сохраняет `run.cost` в таблице результатов даже при ошибке извлечения ответа. |
| `show_trace_from_disk(id_, model, traces_dir)` | Читает уже сохранённый трейс вопроса по `id` и печатает его через `show_trace` — позволяет разобрать провал без повторного (платного) вызова агента. |
| Обновлённый `SYSTEM`-промпт | Добавлены явные правила формата финального ответа: отвечать на языке вопроса, но числа/даты/цитаты брать дословно из источника без перевода; даты — в формате «число месяц» без года; соотношения вида «4 of 5» приводить полностью, а не только первым числом. |

## Итоговая таблица и график

Агент — `gpt-4o-mini` с двумя инструментами: `web_search` (поиск по открытому вебу через
DuckDuckGo HTML, без API-ключа, работает и на русском) и `read_page` (чтение полного текста
страницы, а не только вступления). Прогон на всех 148 вопросах после серии правок (свой
`final_answer`, промпт с явными правилами формата ответа, мягкая проверка `loose_match` в
дополнение к строгой):

| Конфигурация | Точность (agent_ok) | Цена задачи | Cost per correct |
|---|---|---|---|
| Sonnet 4.6, без инструментов | 0% (0 из 148, по построению датасета) | ≈0.33 ¢ (по замеру на 23 своих вопросах: $0.076 / 23) | не определена (нет верных ответов) |

| **Наш агент**: gpt-4o-mini + `web_search` + `read_page` | **64% (94 из 148)** | **≈0.056 ¢** ($0.083 / 148) | **≈0.088 ¢** ($0.083 / 94) |

## Вывод: подтвердился ли тезис курса

**Да, подтвердился — причём в самой сильной возможной форме.** На свежих вопросах у Sonnet 4.6
без инструментов нет ни единого верного ответа из 148 (0%), то есть цена его верного ответа
формально бесконечна — сильная модель здесь категорически бесполезна сама по себе, она физически
не видела эти события в обучении. Дешёвый агент с двумя простыми инструментами (веб-поиск без
платного API + чтение страницы целиком) решает 64% вопросов за $0.083 суммарно — это тот случай,
когда «дешёвая модель + инструменты» не просто дешевле сильной модели-одиночки при том же
качестве, а вообще единственный работающий вариант. При этом наш агент с чтением полной страницы
дал точность на 6 п.п. выше ориентира из задания (72/125 = 58% у агента, читавшего только
вступление Wikipedia) — значит именно `read_page` (а не просто более широкий поиск) и добавил
основную часть прироста, потому что нужный факт часто спрятан глубже первого абзаца статьи.

**Где тезис не подтвердился (точнее, где агент всё равно спотыкается) и почему:**

- **Форматные расхождения, а не фактические ошибки.** `fresh-10` (`Twelve` vs `12`),
  `fresh-26`/`fresh-28` (`nine` vs `9 people were injured`), `fresh-41` (`Thirty thousand people`
  vs `30,000`), `fresh-42` (`Prime Minister Narendra Modi` vs `PM Narendra Modi`) — агент нашёл
  верный факт, но записал число словом вместо цифры или сократил титул; строгая проверка на
  подстроку и даже `loose_match` (не переводит текстовые числительные в цифры) считают это
  ошибкой, хотя по сути агент прав.
- **Языковой конфликт вопрос/источник.** `my-20` — вопрос по-русски, а золотой ответ `4 of 5`
  дословно взят из английской статьи; агент по-русски (разумно) отвечает «4 из 5», что не может
  совпасть побуквенно с английским «of». Это не баг модели, а изъян конкретного вопроса в
  датасете — при следующей итерации такие ответы стоит упрощать до языконезависимого ядра факта
  (например, оставить только число).
- **Реальные фактические промахи.** `fresh-4` (агент прочитал не ту новость про Викторию,
  Австралия), `fresh-6` (нашёл другую цифру пострадавших), `fresh-29`/`fresh-36` (близкое, но не
  то число погибших), `fresh-31` (не нашёл источник и сдался с «информация недоступна») — здесь
  подвела не модель, а дешёвый бесплатный поиск DuckDuckGo: он не всегда поднимает наиболее
  релевантную и полную страницу в топ-5 результатов, а сайты вроде `en.wikipedia.org` иногда не
  укладываются в таймаут 15 секунд на чтение (видно в трейсе `my-20`).

Итог: тезис курса работает даже лучше, чем на школьной арифметике семинара, — там сильная модель
хотя бы иногда решала задачи и без инструментов, а здесь у неё принципиально нет шансов. Основной
источник оставшихся 36% провалов — не слабость дешёвой модели-«мозга» агента, а качество
бесплатного инструмента поиска и строгость автоматической проверки формата, а не разум агента.
